# 로컬 REST 통합 검사

`smoke-local.mjs`는 실제 로컬 백엔드에 로그인하여 요청 생성·조회·취소, 중복 제한,
Refresh 회전·재사용 거절·로그아웃까지 13개 항목을 검사한다. Node 24 기본 모듈만 사용한다.
매칭·채팅·메일 발송·실제 카카오 응답까지 검증하는 도구는 아니다.

## 준비와 실행

1. 개발용 MySQL·Redis 및 `local` 백엔드를 실행한다(루트 README 참고). `JWT_SECRET`이 필요하다.
2. **이 검사에만 사용하는 가입 완료 테스트 계정**을 준비한다. 로그아웃 검사는 그 계정의 모든 Refresh
   토큰을 폐기하므로 평소 브라우저에서 쓰는 계정과 분리한다. 스크립트는 사용자 생성·비밀번호 변경·DB 초기화를 하지 않는다.
3. 자동 검사에서는 백엔드 실행 시 `KAKAO_REST_API_KEY`를 비워 fallback을 사용한다. 클라이언트 스크립트가
   서버의 외부 API 호출을 막아 주지는 않는다. 매칭 엔진이 실행되는 환경은 대상이 아니다.

저장소 루트에서 실행한다. 아래 비밀번호 입력 예시는 **Bash** 기준이며 화면·셸 기록에 비밀번호를 쓰지 않는다.

```bash
export SMOKE_BASE_URL=http://127.0.0.1:8080
export SMOKE_EMAIL=smoke-test@jnu.ac.kr  # 실제로 준비한 테스트 계정
read -r -s -p '테스트 계정 비밀번호: ' SMOKE_PASSWORD
export SMOKE_PASSWORD
node deploy/scripts/smoke-local.mjs
unset SMOKE_PASSWORD
```

백엔드가 살아 있어야 한다. 성공 시 `로컬 통합 검사 13개 통과`, 실패 시 종료 코드 1을 반환한다.
토큰·비밀번호·응답 본문은 로그로 출력하지 않는다. HTTP 요청별 제한 시간은 10초이며 리다이렉트는 거절한다.

## 기존 데이터와 실패 처리

- `localhost`·`127.0.0.1`·`[::1]`의 HTTP 주소만 허용한다. 운영 서버·터널에 실행하지 않는다.
- 로그인 뒤 기존 진행 요청이 있으면 생성·취소하지 않고 중단한다.
- 이번 실행의 생성 응답에서 본인 소유로 확인한 ID만 취소한다. 조회 응답에서 다른 ID를 받거나 생성이 409로
  실패해도 그 요청은 취소하지 않는다. 정상 종료 시 진행 요청이 없음을 확인한다.
- 중간 실패 시 확인된 요청 ID를 `finally`에서 정리한다. 취소가 실패하면 ID와 실패 사실을 보고한다.
- 생성 응답을 받기 전 연결이 끊기거나 프로세스가 강제 종료되면 ID를 모르므로 정리를 보장할 수 없다.
  재실행 전 테스트 계정의 요청 상태를 확인한다. 이를 해결하려고 DB 전체 삭제나 Redis `FLUSHALL`을 실행하지 않는다.

## CI와 자체 회귀 검사

```bash
node --test load/k6/ride-requests.test.cjs deploy/scripts/smoke-local.test.mjs
```

CI의 `로컬 검증 스크립트 회귀 검사` job이 위 명령을 실행한다. 네트워크 없는 대역 검사이므로 실제 API 통합 검사와
구분한다. DB·브라우저·외부 서비스나 추가 패키지가 필요 없다. 실제 REST 검사는 위 계정·서버를 준비해 별도로 실행한다.
