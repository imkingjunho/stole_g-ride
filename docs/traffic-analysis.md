# 광주 시간대별 교통 분석 기준

> 상태: **분석 기준 정리·공식 데이터 목록 확인, 원문 수집·실측 분석 전** (2026-10-28).
> 공용 문서 관리: 이승민. 데이터 수집·분석: 송준호 [T3-1](roles/송준호.md), 베타 성과 산출: 송준호 T3-2. 매칭·통계 구현 및 튜닝: 서준.
> 근거: [PRD](PRD.md) §5(알고리즘), §10(성능 목표), §16(성과 지표), 부록 B(데이터 소스). 이 문서는 이승민 T3-4의 서버 성능 보고서와 별개다.

## 1. 목적과 현재 상태

전남대 주변 6개 거점의 등하교·귀향 시간대 이동량을 비교하고, 서비스 내부 요청량과 함께 매칭 파라미터 검토의 근거로 사용한다. **도로 교통량·대중교통 승하차량은 택시 동승 요청 수나 매칭 성사율을 직접 의미하지 않는다.** 서로 다른 지표를 하나의 교통량으로 합치지 않는다.

현재 저장소에는 분석용 원천 데이터와 재현 가능한 집계 결과가 없다. 아래 공식 출처는 목록·설명만 확인했으며, 원문 파일의 열·결측·공간 범위는 검증 전이다. 특정 피크 시간대나 개선 효과를 실측 결과로 제시하지 않는다.

30초 매칭 tick은 PRD의 설계 기본값이다. 현재 `matching/`에는 이력 스텁만 있고 `domain/matching.yml`은 설정 예정 주석뿐이며, `stats` 계측도 구현 전이다. `ride`의 30초 만료 처리 스케줄러와 매칭 tick을 구분한다. 예약 매칭·시간대별 자동 설정·거점별 우선순위는 향후 검토 제안이며 현재 제공 기능이 아니다.

## 4. 분석 단위와 전처리

1. 데이터별 실제 관측 시작·종료일을 고정한다. 가능한 최근 연속 4주 이상을 우선하되 확보하지 못하면 기간 부족을 표시한다. 평일·주말 및 요일별로 나누고 공휴일·방학·행사일을 별도 표시한다.
2. 모든 시각은 `Asia/Seoul`로 해석하고 원천 시간대가 다르면 변환한다. 집계 구간은 시작 포함·끝 제외다. 기본 30분으로 집계하되 **1시간 원본을 30분 값으로 쪼개거나 보간하지 않는다.** 서로 비교하는 자료는 더 거친 공통 해상도로 맞춘다.
3. 교통량·승하차 건수는 합계, 속도 등 평균형 자료는 지표 정의에 맞는 평균을 사용하고 단위를 기록한다. 승차·하차를 구분하며 승하차 거래 건수를 고유 이용자 수로 해석하지 않는다.
4. 좌표 자료는 허브 반경 500m를 기본으로 사용한다. 정류장은 식별자·좌표를 연결하고, 교차로는 거리와 관측 방향을 확인한다. 격자 자료는 허브 포함 격자를 우선하되 격자 크기·경계 여부를 표시한다. 지점·격자 값을 거점의 실제 수요로 단정하지 않는다.
5. 출처의 전체 식별 차원(날짜·지점·노선·방향·시간·차종/지표 등)을 확인한 뒤 동일 레코드의 중복만 제거한다. 같은 정류장·시간의 서로 다른 노선은 별도 관측이다. 캠퍼스 거점들의 500m 반경은 겹칠 수 있으므로 중복 관측 지점을 표시하고 **거점별 값을 더해 도시 전체 교통량으로 제시하지 않는다.**
6. 결측값은 0으로 대체하지 않는다. 실제 관측된 0과 결측을 구분하고 유효 관측 수·기대 관측 수를 함께 기록한다. 동일 시간대의 날짜별 평균과 중앙값을 모두 산출한다.
7. 상대 지수는 **동일 거점·출처·지표·요일·해상도·분석 기간**의 일중 슬롯을 기준으로 산출한다. 슬롯별 날짜 평균을 `x(h)`라 할 때 `index(h) = x(h) / median_h(x(h))`다. 기준 중앙값이 0 또는 결측이면 미산출로 남기고, 원값과 관측 수를 함께 제시한다.

원본 보관 시 데이터명, 제공기관, 원문 URL, 관측 기간, 다운로드 일시, 이용 조건, 파일명·SHA-256, 열 설명·단위, 좌표계, 공간 연결 방법, 집계 스크립트 버전을 기록한다. 원본은 이용 조건에 맞는 공유 위치에 보관하고 인증키·개인 식별정보를 저장소에 올리지 않는다.

## 5. 산출 지표와 계측 준비

### 외부 교통 지표

| 지표 | 정의 |
|---|---|
| `traffic_index` | 차량 교통량의 상대 지수(§4.7) |
| `pedestrian_index` | 실제 유동인구 자료를 확보했을 때만 산출하는 상대 지수 |
| `transit_boarding_index`, `transit_alighting_index` | 대중교통 승차·하차 건수의 상대 지수. 유동인구와 구분 |
| `taxi_activity_index` | 별도 공개 택시 운행 자료 확보 후 산출할 상대 지수. 현재 미산출 |
| `valid_observations`, `expected_observations` | 실제 사용 관측 수·집계 구간에 기대한 관측 수 |

### 서비스 내부 검증 지표

거점과 **요청 생성 시각**으로 묶은 동일 요청 집합(코호트)을 기준으로 계산한다. 운영에서 실제 저장된 고유 `requestId`만 포함하고 검증 실패·데모·부하 테스트 요청은 제외한다. 취소·만료 요청은 분모에서 빼지 않는다. 같은 요청의 재매칭·재확정은 한 번만 센다.

| 지표 | 정의 |
|---|---|
| `request_count` | 해당 코호트의 고유 요청 수 |
| `matched_request_count` | 해당 코호트 중 최초 그룹 확정에 도달한 고유 요청 수 |
| `match_rate` | `matched_request_count / request_count`. 분모가 0이면 미산출 |
| `matched_group_count` | 거점·최초 확정 시각 구간별 고유 성사 그룹 수. 요청 코호트와 별도의 운영 지표이며 성사율의 분자가 아님 |
| `mean_wait_seconds` | 성사 요청별 `first_confirmed_at - created_at`의 산술평균. PRD §16의 **평균 300초 이하** 목표 |
| `median_wait_seconds` | 같은 성사 요청 표본의 대기시간 중앙값. 보조 지표 |
| `route_api_call_count` | 실제 카카오 길찾기 HTTP 시도 수(재시도 포함). 캐시 적중·키 누락으로 외부 호출 없는 fallback은 제외. 호출 시각 기준 |

예를 들어 요청 4건이 2인 그룹 2개로 모두 확정되면 성사율은 `4 / 4 = 100%`다. 대기시간은 성사 요청만의 통계이므로 성사율·표본 수와 함께 제시한다. 집계 기준 시각과 미결 요청 수를 기록하고 결과가 확정되지 않은 코호트는 잠정치로 표시한다. 최초 성사 후 해체·취소·탑승 완료 여부는 별도 결과 지표로 다룬다.

**계측은 후속 구현 항목이다.** 현재 `RideRequest`에는 최초 확정 시각이 없고 `GroupConfirmed`는 `groupId`, `userIds`만 전달한다. 이 이벤트만으로 과거 요청 ID·발생 시각을 복원할 수 있다고 가정하지 않는다. 서준·이승민이 요청↔그룹 연결, 최초 확정 시각 보존, 중복 이벤트 처리, 테스트 요청 제외 방법을 합의한 뒤 계측한다. API의 `matchedCount` 의미와 0건·잠정치 표현도 그때 명확히 한다. 이 문서 반영으로 `contract/`, API 스키마 또는 DB를 변경하지 않는다.

외부 지표만으로 `match_rate`를 계산하지 않는다. 내부 로그가 쌓인 뒤 같은 기간·공간·해상도의 자료로 비교하고, 상관관계를 인과관계로 해석하지 않는다.

## 7. 매칭 파라미터 검토 규칙

실제 데이터와 내부 계측을 확보한 뒤 적용할 검토 절차다. 현재 설정이나 사용자의 요청 조건을 자동 변경하는 규칙이 아니다.

1. 외부 이동량과 `request_count`가 모두 높은 구간에서는 PRD 설계 기본값인 30초 tick을 기준으로 후보 평가 시간·API 호출 수·성사율을 함께 검증한다.
2. 외부 이동량은 높지만 요청이 적으면 교통량만으로 대기시간을 늘리지 않는다. 예약 매칭 등 새로운 기능은 별도 요구사항으로 검토한다.
3. 요청은 많고 성사율은 낮으면 같은 출발 거점·목적지 권역·출발 시간창·성별 조건의 분포를 먼저 확인한다. 기존 요청의 `maxDetourRatio`나 `maxWaitMin`을 임의로 늘리지 않는다.
4. `mean_wait_seconds`가 300초를 넘으면 성사율·미결/만료·표본 수와 함께 원인을 확인한다. 중앙값만 낮다는 이유로 PRD 목표를 충족했다고 판단하지 않는다.
5. 변경 전후 각각 최소 1주의 동일 요일·시간대·거점을 비교한다. 표본 수·결측·방학/행사 영향을 함께 보고, 요청이 적거나 기간 조건이 다르면 결론을 보류한다. 실험 전에 판정 기준·관측 기간·되돌릴 조건을 정한다.
6. 현재 요청 선택지는 대기 5/10/15/20분, 우회율 10/20/30%다. 선택지·기본값 변경은 이승민의 요청 검증·API와 송준호의 화면을 함께 조정한다. 매칭 tick·가중치는 서준 담당이며 사용자 우회 상한과 전원 절감 조건(PRD §5)을 유지한다.

## 8. 담당별 후속 작업과 완료 기준

| 담당 | 후속 작업 | 완료 증거 |
|---|---|---|
| 송준호 T3-1 | 버스 원문·정류장 좌표 우선 수집, 도시철도/교차로 보조 자료 검증, 6개 거점 공간 연결 | 원본 메타데이터·집계 스크립트·관측 범위·거점/요일/시간대별 표 또는 그래프. 미관측 거점은 명시 |

| 이승민 T2-4 | 공용 문서 정합성 유지, 합의된 계측 계약·요청 조건 변경 접수 | PRD·이 문서·API 설명의 일치 및 필요 시 계약/설정 변경 검증 |
