## 담당 범위

| 구분 | 내용 |
|---|---|
| 패키지 | `backend/.../auth/`, `backend/.../user/`, `backend/.../chat/`, `db/migration/` |
| 담당 FR | FR-01, 02, 03, 04 / FR-20, 21, 22, 23 |
| 1차 도메인 | 인증, 회원, DB 스키마 |
| 2차 도메인 | WebSocket 채팅 (10월 인수) |

## ⚠️ 이 역할의 특수성

**DB 마이그레이션 파일의 단독 오너**다. 다른 팀원이 스키마 변경을 요청하면 본인이 작성한다.
여러 명이 각자 마이그레이션을 만들면 파일명·순서가 충돌하므로 반드시 한 사람이 관리한다.

채팅을 2차 도메인으로 맡는 이유: **WebSocket 핸드셰이크에 JWT 검증이 필요**하기 때문이다.
인증을 직접 만든 사람이 이어받는 게 가장 자연스럽다.

## Phase 1 — DB 스키마 (8월) 🔥 최우선

- [ ] **T1-1. 마이그레이션 도구 설정**
  - Flyway 또는 Liquibase 설정
  - 명명 규칙: `V{날짜}_{순번}__{설명}.sql` (예: `V20260901_01__create_users.sql`)

- [ ] **T1-2. 전체 스키마 작성** — PRD §7 그대로
  - `users`, `hubs`, `ride_requests`, `match_groups`, `match_members`, `chat_messages`, `refresh_tokens`, `reports`
  - 인덱스: `ride_requests(status, hub_id, depart_at)`, `match_members(user_id)`, `chat_messages(group_id, created_at)`
  - **팀 전원이 이 스키마 위에서 엔티티를 만든다. 8월 1~2주차에 반드시 완료**

- [ ] **T1-3. 거점 초기 데이터**
  - `hubs` 테이블 seed: 전남대 정문·후문·예대삼거리, 경신여고, 유스퀘어, 광주송정역
  - ⚠️ 정확한 좌표는 송준호에게 요청

## Phase 2 — 인증 (9월)

- [ ] **T2-1. 회원가입 및 웹메일 인증** — FR-01
  - `POST /api/auth/signup` — `@jnu.ac.kr` 도메인만 허용
  - 6자리 인증 코드 메일 발송 (Spring Mail), 유효시간 10분
  - Redis에 코드 저장 (TTL 10분)
  - 5회 실패 시 30분 잠금
  - `POST /api/auth/verify` — 코드 검증 및 가입 완료

- [ ] **T2-2. JWT 인증** — FR-02
  - Access 30분 / Refresh 14일
  - **Refresh 토큰 회전(rotation)** — 재발급 시 기존 토큰 무효화
  - Refresh 토큰은 해시하여 `refresh_tokens` 테이블에 저장
  - `POST /api/auth/login`, `POST /api/auth/refresh`
  - `JwtAuthenticationFilter` + Spring Security 설정
  - ⚠️ Security 설정은 `config/`에 있으므로 이승민과 협의

- [ ] **T2-3. 프로필** — FR-03
  - 닉네임(고유), 성별(**등록 후 변경 불가**), 학과·학년(선택)
  - **실명·전화번호는 저장하지 않는다** (개인정보 최소 수집 원칙)
  - `@AuthenticationPrincipal`로 현재 사용자 주입되도록 구성

- [ ] **T2-4. 신고 및 이용 제한** — FR-04
  - `POST /api/reports` — 매칭 이력 기준으로만 신고 가능
  - 누적 3회 시 `status = SUSPENDED`, 7일 제한

## Phase 3 — WebSocket 채팅 (10~11월)

- [ ] **T3-1. STOMP 설정 및 인증 연동** — FR-20
  - `/ws/chat/{groupId}` 엔드포인트
  - **핸드셰이크 시 JWT 검증** (`ChannelInterceptor`)
  - 해당 그룹 멤버만 구독 가능하도록 인가 처리
  - ⚠️ STOMP 기본 설정은 이승민의 `/ws/queue`와 공유. 설정 충돌 없도록 협의

- [ ] **T3-2. 메시지 송수신**
  - `ChatMessage` 저장 및 브로드캐스트
  - 매칭 성사 시 채팅방 자동 개설, 시스템 메시지 발송

- [ ] **T3-3. 휘발성 처리** — FR-21
  - 탑승 완료 또는 개설 후 3시간 경과 시 메시지 **물리 삭제**
  - 스케줄러로 주기 정리
  - 그룹 해체 시 시스템 메시지 후 5분 뒤 삭제 (E-10)

- [ ] **T3-4. 정형 메시지** — FR-22
  - "도착했어요", "5분 늦어요", "출발합니다" 퀵 버튼용 `type = QUICK`

- [ ] **T3-5. 연락처 마스킹** — FR-23
  - 전화번호(`010-XXXX-XXXX` 등), 이메일, 카카오톡 ID 패턴 자동 마스킹
  - 정규식 유틸을 `chat/util/`에 작성

## 포트폴리오 정리 포인트

> "JWT Refresh 토큰 회전 방식의 인증 체계를 설계하고, 학교 웹메일 인증으로
> 폐쇄형 커뮤니티를 구현. WebSocket 핸드셰이크 단계의 인증·인가를 연동하여
> 그룹 멤버만 접근 가능한 실시간 채팅을 구축."

**"인증과 실시간 통신을 연결해 본 경험"**은 신입 백엔드에서 흔치 않은 강점이다.
WebSocket에서 왜 HTTP 필터가 아니라 `ChannelInterceptor`를 써야 하는지 설명할 수 있게 정리해 둘 것.
