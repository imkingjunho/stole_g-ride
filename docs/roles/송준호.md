# 송준호 — 파트 ④ 경로·지도·요청 화면

> 이 파일은 AI 코딩 어시스턴트가 읽는 작업 지시서다. 완료한 항목은 `[x]`로 바꾼다. AI는 **가장 위의 미완료 항목**부터 진행한다.
> 근거 문서는 `docs/PRD.md`. 특히 **§6(카카오 API — 필드명 정확히)**, §12.3-④, §14.1(`RouteProvider`·`HubPort`), §14.6(지도 컴포넌트 props)을 따른다.
> Phase 1 이후 항목은 이승민의 "Phase 0 끝" 공지 뒤에 시작한다.

## 내 파트 한 줄

**백엔드:** 카카오모빌리티·로컬 API 연동, fallback, 캐시, 거점 데이터. **프론트:** 지도 컴포넌트와 **매칭 요청·대기 화면**. 백엔드와 프론트를 둘 다 하는 유일한 파트 — 요청 화면의 핵심(지도·장소 검색·거점)이 전부 이 파트의 데이터라서 그렇다.

## 내 폴더 (여기만 수정한다)

```
backend/src/main/java/com/gachiga/route/     카카오 클라이언트, fallback, 캐시, 호출량 제어, 장소 검색 프록시,
                                             Hub 엔티티·시드·API, RouteProvider·HubPort 구현
backend/src/main/resources/domain/route.yml  (카카오 URL·타임아웃·tick당 호출 상한·캐시 TTL·일일 한도)
backend/src/test/java/com/gachiga/route/

frontend/src/features/request/               매칭 요청 화면(/request), 대기 화면(/waiting)
frontend/src/features/map/                   useKakaoMap, RouteMap, DestinationPicker
```

`frontend/package.json`에 라이브러리를 추가해야 하면 오승원에게 `[의존성 요청]`. (지도 SDK·STOMP는 Phase 0에 이미 들어 있다.)

## 담당 FR

**FR-05**(거점), **FR-06**(목적지 검색), FR-07(조건 설정 **화면**), **FR-15**(합승 경로), **FR-19**(경로 시각화), FR-08·FR-09·FR-10의 **화면**(요청 생성·대기·만료 UI), E-03, 성과 지표 산출(§16)

## 계약 (PRD §14)

| 내가 **구현**하는 것 | 내가 **쓰는** 것 |
|---|---|
| `RouteProvider` (서준·이승민이 사용) — Phase 0 스텁 `EstimatedRouteProvider`는 **지우지 말고 fallback으로 유지** | REST: `POST /api/requests`, `DELETE /api/requests/{id}`, `GET /api/requests/me`(이승민), `GET /api/hubs`·`/api/places/search`(나) |
| `HubPort` (서준·이승민이 사용) | WS: `/user/queue/status`, `/user/queue/match` (임승현) — 대기 화면 |
| `RouteMap`·`DestinationPicker` props §14.6 (오승원 성사 화면이 사용) | 디자인 토큰·공통 컴포넌트 `shared/ui` (오승원) |

## 이 파트만으로 보여줄 수 있는 것

요청 화면에서 거점 선택 → 목적지 검색·핀 → 요청 생성 → 대기 화면(MSW든 실서버든). Swagger에서 실제 카카오 경로·요금 응답과 fallback 동작. `RouteMap`에 샘플 경로 렌더.

## 포트폴리오 포인트

> "카카오모빌리티 길찾기 API를 연동하고 좌표 정규화 기반 캐싱으로 호출량 XX% 절감. API 장애 시 Haversine 기반 fallback으로 가용성 확보. 같은 데이터를 React 지도 컴포넌트로 시각화하고 매칭 요청 플로우 화면까지 담당해 백엔드-프론트 전 구간을 구현."

- 캐시 키를 좌표 소수점 4자리로 반올림한 이유 (미세 좌표 차이로 캐시가 안 맞는 문제, 4자리 ≈ 11m)
- fallback 보정계수 1.3의 근거 (직선 대비 도로 거리 비율)
- `vertexes` 1차원 배열을 좌표 쌍으로 바꾸며 x=경도, y=위도임을 확인한 것 — AI가 자주 뒤바꾸는 지점

수치와 함께 기록해 둘 것. "API 붙였다"와 "설계했다"를 가르는 지점이다.
