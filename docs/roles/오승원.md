# 오승원 — 파트 ⑤ 프론트 기반·핵심 화면

> 이 파일은 AI 코딩 어시스턴트가 읽는 작업 지시서다. 완료한 항목은 `[x]`로 바꾼다. AI는 **가장 위의 미완료 항목**부터 진행한다.

> Phase 1 이후 항목은 이승민의 "Phase 0 끝" 공지 뒤에 시작한다.

## 내 파트 한 줄

프론트의 **기반**(디자인 시스템·라우팅·API 클라이언트·MSW)과 **핵심 화면**(인증, 매칭 성사, 정산 상세, 채팅, 이력). 심사자가 보는 건 결국 화면이다 — **매칭 성사 화면과 정산 상세 화면이 프로젝트의 하이라이트**다. 백엔드를 기다리지 않는다: `docs/api-spec.yaml`에서 타입을 만들고 MSW 위에서 먼저 완성한다.

## 내 폴더 (여기만 수정한다)

```
frontend/                              루트 설정 전부 (package.json, vite.config.ts, tailwind.config.js, tsconfig, .eslintrc …)
frontend/src/app/                      라우터, Provider, 레이아웃, 라우트 가드
frontend/src/shared/                   ui/(디자인 시스템), api/(클라이언트·인터셉터), stores/, ws/(STOMP 래퍼), mocks/(MSW)
frontend/src/features/auth/            회원가입(웹메일→코드→프로필), 로그인
frontend/src/features/group/           매칭 성사 화면, 정산 상세
frontend/src/features/chat/            채팅 화면
frontend/src/features/history/         이력, 누적 절감 대시보드, 프로필(/me)
```

**내 폴더가 아닌 것:** `frontend/src/features/request/`, `frontend/src/features/map/` (송준호), `frontend/src/generated/` (자동 생성 — `npm run gen:api`로만 갱신, 손으로 고치지 않는다).

`package.json`은 내가 관리한다. 송준호가 `[의존성 요청]`을 보내면 추가해서 push 하고 공지한다.

## 계약 (PRD §14)

| 내가 **제공**하는 것 | 내가 **쓰는** 것 |
|---|---|
| `shared/ui` 디자인 토큰·컴포넌트 (송준호가 요청 화면에서 사용) | REST 전부 — `docs/api-spec.yaml` → `npm run gen:api` (이승민 관리) |
| `shared/api/client.ts`, `shared/stores/authStore.ts`, `shared/ws/stompClient.ts` (송준호 대기 화면이 사용) | WS §14.5 — `/user/queue/match`, `/topic/chat/{groupId}`, `/app/chat/{groupId}` (임승현) |
| `shared/mocks` MSW 핸들러 (전원의 목 개발 환경) | `RouteMap` props §14.6 (송준호) — 성사 화면에 배치 |
| 라우트 표 §14.6 | |

API 스펙에 필요한 필드가 없으면 `[계약 변경 요청]`을 이승민에게. **타입을 손으로 만들어 때우지 않는다** — 스펙이 바뀌면 전부 어긋난다.

## 이 파트만으로 보여줄 수 있는 것

`VITE_API_MODE=mock`으로 **PRD §3.2 시나리오 전체를 클릭 한 바퀴** — 백엔드가 하나도 없어도. 이게 프론트 파트의 시연 단위다.

## 완료 기준 (DoD) — 매 작업마다

- [ ] `cd frontend && npm run lint && npm run build` 통과, `any` 없음
- [ ] mock 모드와 real 모드 둘 다 확인 (real은 해당 API가 main에 있을 때)
- [ ] 모바일 360px 뷰포트에서 깨지지 않음, 로딩·에러·빈 상태 있음
- [ ] 이 파일의 체크박스 갱신 → PRD §13.4 루틴으로 main에 push

## 포트폴리오 포인트

> "React 기반 실시간 매칭 웹앱을 설계·구현. OpenAPI 스펙 기반 타입 자동 생성과 MSW 목 서버로 백엔드와 완전 병렬 개발 환경을 구축해 통합 대기시간을 제거. 구간 분할 정산을 사용자가 납득하는 시각화로 옮기고, 베타 테스트 30명 피드백을 반영해 만족도 4.0/5.0 달성."

- MSW + 스펙 기반 타입 생성으로 "백엔드 없이 프론트를 끝까지 만든" 경험 (협업을 설계한 증거)
- 401 → refresh → 재시도 인터셉터 (E-09)를 왜 어떻게 만들었는지
- 정산 상세 시각화의 설계 근거 — 숫자가 아니라 "구간과 인원"을 보여준 이유
