# 오승원 — 프론트엔드 리드 / UI·UX

> 이 파일은 AI 코딩 어시스턴트가 읽는 작업 지시서입니다.
> 완료한 항목은 `[x]`로 바꿔 주세요. AI는 **가장 위의 미완료 항목**부터 진행합니다.
> ⛔ **코드를 쓰기 전에 `docs/WORK-ORDER.md`에서 이 작업의 선행 항목을 확인하세요.** 선행이 안 끝났으면 AI가 멈추고 누가 먼저 해야 하는지 알려줍니다.

## 담당 범위

| 구분 | 내용 |
|---|---|
| 디렉터리 | `frontend/src/` 전체 (단, `features/map/`은 송준호) |
| 담당 FR | FR-05~10, 12, 13, 17의 화면 / 전체 UI·UX |
| 1차 도메인 | 프론트 기반 구조, 디자인 시스템, 인증·요청 화면 |
| 2차 도메인 | 매칭·정산·채팅 화면, 베타 테스트 총괄 |

## ⚠️ 이 역할의 특수성

**혼자 프론트 전체를 맡으므로 백엔드를 기다리면 반드시 일정이 무너진다.**
MSW(Mock Service Worker)로 목 서버를 띄워 **백엔드 완성 전에 화면을 먼저 만든다.**
`docs/api-spec.yaml`만 확정되면 병렬 작업이 가능하다.

10월부터 지도 파트를 송준호가 맡으므로, **그가 올릴 자리(레이아웃, props 인터페이스)를
미리 비워 두고 넘겨야 한다.**

발표와 시연에서 심사자가 보는 건 결국 화면이다. **완성도가 곧 프로젝트 평가다.**

## Phase 1 — 기반 구조 (8~9월) 🔥 최우선

- [ ] **T1-1. 프로젝트 셋업**
  - Vite + React 18 + TypeScript
  - Tailwind CSS, TanStack Query, Zustand, React Router
  - ESLint + Prettier + pre-commit hook
  - 완료 기준: `npm run dev`로 실행된다

- [ ] **T1-2. API 타입 자동 생성**
  - `openapi-typescript`로 `docs/api-spec.yaml` → 타입 생성 스크립트
  - **타입을 손으로 중복 정의하지 않는다**
  - `npm run gen:api` 스크립트로 등록

- [ ] **T1-3. MSW 목 서버**
  - `docs/api-spec.yaml` 기반 핸들러 작성
  - 개발 모드에서만 활성화
  - **이게 있어야 백엔드 없이 화면 개발이 가능하다. 반드시 초반에 구축**

- [ ] **T1-4. 디자인 시스템**
  - 컬러 토큰, 타이포그래피, 간격 스케일 정의
  - 공통 컴포넌트: Button, Input, Card, Modal, Toast, Spinner
  - **모바일 우선(mobile-first).** 학생이 길에서 쓰는 서비스다
  - 완료 기준: 송준호가 지도 컴포넌트를 올릴 때 이 토큰을 그대로 쓸 수 있다

- [ ] **T1-5. 인증 플로우 화면** — FR-01, 02, 03
  - 회원가입(웹메일 입력 → 인증 코드 → 프로필 등록)
  - 로그인, 토큰 자동 갱신 인터셉터
  - 인증 필요 라우트 가드
  - 성별은 등록 후 변경 불가임을 UI에 명확히 안내

- [ ] **T1-6. 법적 고지 문구 배치** — PRD §2.2
  - "본 서비스는 동승자 매칭 및 요금 분담 계산만 제공하며, 택시 호출·운송·결제를 중개하지 않습니다."
  - 온보딩과 매칭 화면 하단에 상시 노출
  - **이 문구 누락은 프로젝트 리스크다. 반드시 넣을 것**

## Phase 2 — 핵심 플로우 (10월)

- [ ] **T2-1. 매칭 요청 화면** — FR-05, 06, 07
  - 출발 거점 **프리셋 버튼** (전남대 정문·후문·예대삼거리 / 경신여고 / 유스퀘어 / 송정역)
  - 목적지 검색 자동완성 (`GET /api/places/search`)
  - 조건 설정: 최대 대기(5/10/15/20분), 동성 매칭 토글, 최대 우회율(10/20/30%)
  - ⚠️ 지도 영역은 송준호 컴포넌트 자리를 비워 두고 props 인터페이스만 정의

- [ ] **T2-2. 대기 화면** — FR-09, 10
  - WebSocket `/ws/queue` 연결, 남은 시간 카운트다운
  - 현재 후보 인원 수 표시
  - 만료 시 "매칭 실패" + 재시도 버튼
  - **대기는 지루하다.** 진행 상황을 계속 보여줘서 이탈을 막는다

- [ ] **T2-3. 매칭 성사 화면** — FR-12, 13, 17
  - 60초 카운트다운 수락/거절
  - **"혼자 12,400원 → 함께 6,900원 (5,500원 절약)"** 형태로 절감액 강조
  - 탑승 순서 / 하차 순서 안내
  - ⚠️ 이 화면이 서비스의 하이라이트다. 가장 공들일 것

- [ ] **T2-4. 정산 상세 화면** — FR-16, 17
  - 구간별 분담 내역을 **시각적으로** 표현 (누가 어디까지 탔고 얼마를 내는지)
  - PRD §5.2의 구간 분할 개념이 한눈에 이해되어야 한다
  - "왜 내가 이 금액인지" 설명이 없으면 사용자가 납득하지 못한다

## Phase 3 — 채팅 및 마무리 (11월)

- [ ] **T3-1. 채팅 화면** — FR-20, 22, 23

- [ ] **T3-2. 탑승 완료 및 이력** — FR-24, 25
  - 탑승 완료 버튼 → 채팅방 종료
  - 이력 목록, 누적 절감액 대시보드

- [ ] **T3-3. 에러 및 예외 상태 UI**

  - 카카오 API fallback 시 "추정치" 배지 (E-03)
  - **예외 화면이 없으면 데모 중에 반드시 사고가 난다**

- [ ] **T3-4. 반응형 및 접근성 점검**
  - 모바일 360px ~ 데스크톱 대응
