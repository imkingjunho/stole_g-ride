# 송준호 서버 반영용 AI 프롬프트

아래 블록을 서버를 실행하는 컴퓨터의 AI 코딩 도구에 그대로 전달한다. 이 문서는 실행 지시서이며 적용 완료 기록은 아니다.

```text
나는 가치가(stole_g-ride)의 송준호이고, 현재 사용자들이 쓰는 백엔드 서버를 내 컴퓨터에서 실행 중이다. 이승민이 main에 올린 2026-11-18 사용성 수정본을 내 서버에 반영해 줘. 기존 계정·요청·동승 내역·DB 볼륨을 보존하고, 현재 공유 주소와 서버 실행 방식을 가능한 한 유지해 줘.

반영 대상:
- 상단 알림: 없애지 않고 3초 후 자동 닫기.
- 요청·대기·그룹·채팅: 거점별 추천 만남 장소와 세부 안내.
- 채팅 입력창 아래 ‘탑승했어요’: 내 완료 기록 저장. 완료 후에도 확정 시점부터 3시간까지 채팅 유지.
- GET /api/history와 GET /api/stats/me: 실제 DB의 본인 완료 내역·통계, 월 필터·페이징.
- 새 요청 커밋 직후 비동기 매칭 평가. 기존 목적지·출발 시간·성별·우회 조건은 유지하며 30초 tick은 복구용으로 유지.
- /password-reset: 학교 이메일 코드 인증 후 새 비밀번호 설정.

진행 순서:
1. AGENTS.md와 docs/deploy.md를 읽고 git status, 현재 브랜치, 실행 중인 서버/DB/프론트/터널을 확인해 줘. 환경변수의 설정 유무만 확인하고 비밀번호·JWT·카카오 키·인증 코드를 출력하지 마.
2. main에서 git pull --rebase origin main으로 최신 코드를 받아 줘. 미커밋 작업이나 충돌이 있으면 내 변경을 지우거나 강제로 덮어쓰지 말고 보존해 줘. 최신 커밋과 변경 파일을 확인해 줘.
3. 백엔드에서 ./gradlew build, 프론트에서 npm ci && npm run lint && npm run build를 실행해 줘. 실패하면 서버를 교체하지 말고 원인을 알려 줘.
4. DB 백업을 만든 뒤 docs/sql/20261118-member-completed-at.sql을 현재 사용하는 MySQL DB에 적용해 줘. match_members.completed_at DATETIME(6) NULL 컬럼만 추가하는 재실행 가능한 SQL이다. 기존 행과 볼륨은 유지해야 한다. docs/schema.sql 전체 재생성, create-drop, docker compose down -v는 실행하지 마. prod의 ddl-auto: validate를 update로 바꾸지 마.
5. 현재 백엔드 실행 방식(bootRun/JAR/Docker)을 확인하고 최신 코드/이미지로 해당 서버만 재시작해 줘. 관련 없는 프로세스는 종료하지 마. 터널은 재시작하지 않고 기존 주소를 유지하는 쪽을 우선해 줘. 어쩔 수 없이 주소가 바뀌면 새 주소와 영향 범위를 알려 줘.
6. 프론트는 누가 어디에 배포하는지 먼저 확인해 줘. Vercel 또는 별도 프론트 소유자의 배포가 필요하면 정확한 환경변수와 재배포 요청을 적어 줘. 권한 없는 프로젝트를 바꾸거나 새 프로젝트를 임의 생성하지 마.
   - 실제 서비스: VITE_API_MODE=real
   - VITE_API_BASE_URL=현재 공개 백엔드 HTTPS origin (/api를 뒤에 붙이지 않음)
   - 프론트 origin은 백엔드 CORS 목록에, 사이트 origin은 카카오 JS 키 허용 도메인에 포함돼야 한다.
   - Vite 환경변수 변경은 프론트 재빌드·재배포가 필요하다.
7. 테스트 계정으로 아래를 검증해 줘. 실제 사용자의 매칭·비밀번호를 대신 바꾸지 마.
   - 로그인과 인증된 /api/users/me가 정상. 비로그인 보호 API는 401.
   - /api/history, /api/stats/me가 404가 아니라 정상 응답. 기록 없는 계정은 빈 목록과 0 통계.
   - 조건이 맞는 테스트 두 계정 요청 시 커밋 직후 평가·그룹 이동. 대기자 수만 같다고 강제 매칭하지 않는다.
   - 채팅에서 탑승 완료 → 내 이력에 1건만 기록 → 기존 메시지 유지 → 보관 시간 안에서 송수신. 중복 클릭으로 기록 증가 없음.
   - 월 필터·페이지 조회와 전체 누적 통계가 일치.
   - 알림이 처음에는 보이고 3초 후 자동으로 사라짐.
   - 비밀번호 찾기: MAIL_HOST/PORT/USERNAME/PASSWORD 설정 여부를 확인. SMTP가 없다면 발송 성공이라고 표시하거나 코드를 화면·로그로 우회 제공하지 마. 메일 설정이 필요하다고 알려 줘. 테스트 메일함으로만 발송 검증해 줘.
8. 최종적으로 적용 커밋, 백엔드/프론트 주소, DB 변경 결과, 테스트 통과·미확인 항목을 한국어로 짧게 정리해 줘. push 완료와 실제 배포 완료를 구분해 줘.

참고:
- 이미 삭제된 과거 채팅은 이번 수정으로 복원되지 않는다.
- 이전 데이터의 완료 시각이 비어 있으면 그룹 완료/확정 시각을 보완값으로 사용한다.
- 만남 안내는 추천 지점이다. docs/pickup-guide.md의 현장 확인 기준에 따라 좌표·가게 이름을 추측해 바꾸지 마.
- 비밀번호 재설정은 기존 Refresh 토큰을 폐기하지만 발급된 Access 토큰은 만료까지 유효하다.
```
