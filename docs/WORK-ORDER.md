# 작업 순서 지도 (선행 의존성)

> **이 문서는 "누가 먼저 해야 하는가"만 다룹니다.** 무엇을 만드는지는 `docs/PRD.md`,
> 각자 할 일은 `docs/roles/{이름}.md`를 보세요.
>
> AI는 **코드를 쓰기 전에 반드시 이 문서에서 선행 항목을 확인**하고,
> 선행이 끝나지 않았으면 **작업을 멈추고 누가 먼저 해야 하는지 알립니다.** (`CLAUDE.md` §0-4)

## 0. 30초 요약

```
8월 1주차, 이 4개가 끝나야 나머지 전부가 움직입니다.

  이승민 T1-1  Spring Boot 프로젝트 생성   ← 백엔드 4명 전원이 여기에 막힘
  임승현 T1-2  DB 스키마                   ← 엔티티 만드는 사람 전원이 막힘
  서준   T1-1  RouteProvider 인터페이스     ← 송준호가 막힘
  오승원 T1-1  프론트 프로젝트 셋업         ← 송준호 지도 파트가 막힘

  + docs/api-spec.yaml v1 (전원 합의, 서준 중재)  ← 오승원이 막힘
```

**신호등**

| 표시 | 뜻 | AI의 행동 |
|---|---|---|
| 🔴 하드 블로커 | 선행 없이는 시작 자체가 불가능 | **멈춘다.** 누가 먼저 해야 하는지 알린다 |
| 🟡 소프트 블로커 | Stub/Mock으로 우회 가능 | **진행한다.** 단, 우회했음을 반드시 알린다 |
| 🟢 없음 | 선행 없음 | 바로 진행 |

> 🟡을 만나면 기다리지 않습니다. 이게 PRD §13.9.2의 핵심이고, 5명이 서로 안 기다리게 하는 장치입니다.

## 4. AI가 선행을 확인하는 방법

작업 시작 전 아래를 **순서대로** 수행합니다.

```
1) docs/WORK-ORDER.md §2에서 지금 작업의 선행 항목을 찾는다
2) 선행 항목 담당자의 docs/roles/{이름}.md에서 그 체크박스를 확인한다
      [x] → 통과
      [ ] → 3)으로
3) 체크박스가 안 찍혔을 수 있으므로 실제 산출물이 있는지 확인한다
      예) 이승민 T1-2  → backend/.../common/response/ApiResponse.java 존재?
          임승현 T1-2  → db/migration/*.sql 존재?
          서준   T1-1  → matching/port/RouteProvider.java 존재?
          오승원 T1-1  → frontend/package.json 존재?
          api-spec v1  → docs/api-spec.yaml 존재?
      존재하면 통과하되, "체크박스를 [x]로 갱신하라"고 알린다
4) 그래도 없으면 등급에 따라
      🔴 → 코드를 작성하지 않고 아래 §5 정지 메시지를 출력한다
      🟡 → Stub/Mock으로 우회해 진행하고, 우회 사실을 반드시 알린다
```

## 5. 정지 메시지 형식

선행이 미완료(🔴)일 때 AI는 코드를 쓰지 않고 이렇게 알립니다.

```
⛔ 작업 순서 확인 필요 — 코드를 작성하지 않았습니다

하려던 작업   : 송준호 T1-2 (KakaoRouteProvider 구현)
막고 있는 선행 : 서준 T1-1 (RouteProvider 인터페이스 정의) — docs/roles/서준.md 에서 [ ] 미완료
먼저 할 사람   : 서준

이유 : 인터페이스가 확정되지 않은 상태에서 구현하면 메서드 시그니처와
       RouteResult 필드가 달라져 나중에 양쪽 다 고쳐야 합니다.

지금 할 수 있는 선택지
  A. 서준에게 T1-1을 먼저 끝내달라고 요청한다  ← 권장
  B. 선행이 없는 송준호 T1-1(거점 좌표 수집)을 먼저 한다
  C. 이미 끝났는데 체크가 안 된 것이라면 알려주세요. 확인 후 진행합니다
```

우회 가능(🟡)일 때는 멈추지 않고 이렇게 알립니다.

```
🟡 선행 미완료 — Stub으로 우회해 진행했습니다

미완료 선행 : 송준호 T1-2 (KakaoRouteProvider)
우회 방법   : FixedRouteProvider(고정값)로 개발·테스트 진행
나중에 할 일 : 실제 구현 완료 후 Bean 교체 + 통합 테스트 재실행
```

## 6. 순서가 이미 뒤바뀐 뒤에 발견했다면

되돌리는 것보다 **맞추는 것**이 쌉니다. 상황별 처방:

| 상황 | 처방 |
|---|---|
| 인터페이스보다 구현이 먼저 나왔다 | 구현을 지우지 말고, 그 구현의 시그니처를 놓고 **양쪽이 5분 통화 후 인터페이스를 확정**한다. 그 다음 구현을 맞춘다 |
| 스키마보다 엔티티가 먼저 나왔다 | 엔티티 기준으로 임승현이 마이그레이션을 작성하되, **PRD §7과 다른 부분은 PRD를 따른다** |
| `common/` 없이 응답을 만들었다 | 컨트롤러 반환 타입만 `ApiResponse<T>`로 감싼다. 로직은 건드리지 않는다 |
| api-spec 없이 프론트 타입을 손으로 짰다 | 손타입을 지우고 `npm run gen:api`로 재생성. **손타입을 남기면 계속 어긋난다** |
| 좌표를 임의로 넣었다 | 송준호 실측값으로 seed 마이그레이션을 **새 버전 파일로 추가** (기존 파일 수정 금지) |

> 되돌릴지 말지 애매하면 **일단 멈추고 팀 단톡방에 물어보세요.** 혼자 3시간 붙잡는 게 가장 손해입니다.

## 7. 이 문서 갱신 규칙

- 작업을 끝내면 `docs/roles/{이름}.md`의 체크박스를 `[x]`로 바꾼다. **이게 다른 사람의 출발 신호다.**
- 새 작업(T번호)이 생기면 §2 표에 선행을 함께 적는다.
- 선행 관계 자체를 바꾸려면 PR로 진행하고 전원에게 공지한다.
